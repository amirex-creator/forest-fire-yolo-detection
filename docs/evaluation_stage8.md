## 六、错误案例分析（conf=0.25，匹配 IoU=0.5）

### 6.1 总体计数（扫描全部 3,229 张）

| 项目 | 数量 |
| --- | --- |
| 命中 TP | 2,095 |
| 误报 FP | 1,239 |
| 漏检 FN | 1,783 |
| 含误报的图片 | 769 张 |
| 含漏检的图片 | 907 张 |

**按类别拆分**：

| 类别 | 漏检 FN | 占比 | 误报 FP | 占比 |
| --- | --- | --- | --- | --- |
| fire | 1,143 | 64.1% | 758 | 61.2% |
| smoke | 640 | 35.9% | 481 | 38.8% |

火焰类既是主要漏检来源也是主要误报来源，与第三节的指标结论一致。

### 6.2 漏检的直接观察（看图得到，不是推测）

保存的漏检样本（`outputs/predictions/error_cases_*/missed/`，12 张 + 总览图）显示：

1. **夜间监控画面**的火焰只占很小一块亮斑，模型完全没检出（`AoF04054`、`AoF04055`、`AoF04562`）；
2. **远处/大范围烟羽**（占画面 60% 以上）在白天逆光、低对比度时被漏掉（`AoF04489`、`AoF04605`、`AoF05097`）；
3. 漏检的 top-20（按标注框面积降序）面积占比 **0.655–0.966**，说明**大目标也会漏**，
   不是"只漏小目标"——这点与直觉相反，值得在论文里讨论（大烟羽边缘弥散、与云雾/天空颜色接近）。

### 6.3 误报的直接观察

保存的误报样本（`.../false_alarm/`，12 张 + 总览图）显示：

1. 误报**高度集中在画面上部的天空/地平线亮带**——模型把明亮的天空边界当成了烟雾/火焰（`AoF00115`、`AoF00116`、`AoF00117`、`AoF00329`、`AoF00374`、`AoF01134`）；
2. `AoF00115/116/117` 是**同一摄像头近乎连续的三帧**，三帧都误报同一位置——说明这是系统性偏差，不是偶发；
3. top-20 误报的置信度 **0.691–0.795**，**很高的置信度**。这意味着：简单把 `conf` 从 0.25 提高到 0.5 **解决不了**这批误报。

### 6.4 从这两个观察能推出的改进方向（尚未实施）

1. 数据层面：补充"只有天空/地平线、没有烟"的负样本；对现有负样本做亮度增强，压掉亮带先验；
2. 训练层面：提高火灾/烟雾的标注一致性，或引入更难负样本的在线挖掘；
3. 后处理层面：对"贴画面上缘、面积小于某阈值"的框加惩罚（会牺牲一部分真阳性，需实验验证）；
4. 评价层面：把上述规则作为**下一轮实验**的内容，不能直接改 test 集指标。

## 八、关于"只评价了一次"的说明（可复核）

第一次运行发现一个**代码 bug**：分类别实例数取了 `Metric.nt_per_class`，
而该字段实际挂在 `DetMetrics` 上，导致实例数全部显示 0。修正为**直接读标签统计**后重跑了一次。

两次运行的结果对比（真实核对）：

| 项目 | 第一次 | 第二次 |
| --- | --- | --- |
| Precision / Recall | 0.6288 / 0.5558 | **完全相同** |
| mAP50 / mAP50-95 | 0.6007 / 0.3140 | **完全相同** |
| TP / FP / FN | 2,095 / 1,239 / 1,783 | **完全相同** |
| 分类别四项指标 | — | **完全相同** |
| 分类别实例数 | 0（bug） | 1,688 / 2,190（正确） |

**这说明评价过程是确定性的、可复现的**；两次运行**没有改动任何训练参数或数据划分**，
test 集也没有用于调参，因此不存在"跑两次挑好的"问题。

## 十、局限与偏差（必须写进论文）

1. **近似分组**：数据划分按感知哈希近似分组（原始文件名里的视频/摄像头 ID 已被抹除），
   同一事件的图片可能被分到不同集合 → 指标**可能偏乐观**；
2. **跨集合近似重复**：阶段五统计到 19 组跨集合近似重复图片（约 0.09%），会抬高测试指标；
3. **数据集不是纯森林场景**：D-Fire 含城市、工业、海岸、夜间监控画面（本阶段样本图里就能看到），
   不能宣称"森林专用模型"；本文结论只适用于"野外/监控场景的烟与火"；
4. **单类别不平衡**：fire 实例（2,190）多于 smoke（1,688），且 fire 指标明显更低；
5. **标注噪声**：test 集 3,878 条标注中含极少量退化/越界框（全数据集 26 条），未逐条剔除；
   抽样时也发现过"画面有淡淡烟羽但标注为空"的疑似漏标（阶段五记录 `WEB00349.jpg`）；
6. **只训练了 10 epoch**：训练曲线仍在上升、未见平台期，因此上述指标**不是该模型的上限**；
7. **错误案例明细只落盘前 20 条**（按置信度/面积排序），完整逐框清单未保存；
8. **未做 CPU 推理对比**，仅报告 GPU 数字。

## 十一、复现方式

```powershell
# 完整评价（指标 + 图表 + 错误案例）
.\.venv\Scripts\python.exe evaluate.py

# 只算指标，不收集错误案例
.\.venv\Scripts\python.exe evaluate.py --no-error-cases

# 只重写 metrics.md（不重跑模型）
.\.venv\Scripts\python.exe evaluate.py --rebuild
```

输出：`outputs/reports/metrics.json`、`outputs/reports/metrics.md`、
`outputs/figures/eval_<时间戳>/`、`outputs/predictions/error_cases_<时间戳>/`。

> 模型识别结果仅供辅助分析，需人工核实；本系统不做森林火灾预警，不能仅凭检测结果确认真实火灾。
